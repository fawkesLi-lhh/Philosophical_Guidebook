# Windows 文件名非法字符导致静默写入失败

## 场景

脚本写文件（含中文书名）后 stdout 打 OK，但文件是 0 字节或文件名被截断。当日反杜林论 `261014-恩格斯-反杜林论(英译:科学…).md` 实际落盘为 `261014-恩格斯-反杜林论(英译`——冒号截断、内容全丢，脚本毫无报错。

## 验证环境

2026-10-15，Windows（Git Bash + Python pathlib.write_text）。

## 方法

### 1. 文件名白名单

生成文件名时强制过滤，只放行：

```python
import re
def safe_name(s: str) -> str:
    # 只保留 中文/字母/数字/圆点/连字符/下划线/空格转下划线；其余全丢
    s = re.sub(r'[\\/:*?"<>|()（）:：]', '', s)
    return s.strip('. ')
```

被禁的最常见的坑：`:`（Windows 盘符语法）、`？`、`<`、`|`、**未闭合或嵌套的括号也有风险**（当日截断点就在括号处）——干脆全去。

### 2. 全量体检抓漏网（收尾必跑）

```python
from pathlib import Path
for f in Path('texts').glob('*.md'):
    if f.stat().st_size == 0:
        print(f'{f.name}: EMPTY')   # 静默失败件
```

写入方（脚本）报 OK 不可信——Windows 对非法路径的失败可能发生在 open 之后的系统调用层，Python 异常未必抛回。**验证写入结果本身，而不是信任写入方。**

### 3. 修复流程

发现 0 字节文件：删掉 → 从 sources 原始文件重跑标准化（幂等，脚本是纯函数）→ 再体检。

## 失败清单

| 尝试 | 结果 | 原因 |
|---|---|---|
| 信任脚本 stdout 的 OK | 漏检数小时 | 异常没抛到脚本层 |
| 逐个目测文件列表 | 差点漏掉 | 截断后的名字看起来「像正常文件名」 |

## 适用边界

- Git Bash 的 ls 显示会把截断名显示得和正常名差不多，目测不可靠，必须程序化体检。
- Linux/macOS 无此问题（文件名仅禁 `/` 和 NUL），但跨平台项目仍建议白名单。
